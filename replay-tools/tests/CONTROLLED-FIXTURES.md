# Next controlled fixture: command semantics

The committed wire fixture validates byte decoding and packaging. It does not prove game-engine outcomes. Do not promote compatibility on its strength alone.

Create one short current-build unlocked-team game, recorded from two human participants, with a written action log and synchronized video. Include game/build/save versions, data and mod identifiers, lobby settings, recorder identities, source SHA-256 values, and the timing reference in the fixture manifest. Each participant keeps the original recording. Test-corpus retention is a deliberate development choice separate from production upload retention.

| Step | Controlled action | Check against canonical evidence and video |
|---|---|---|
| 1 | Queue five villagers individually from one TC; allow two to complete. | Five requests and correct producer ID; two observed engine completions. These counts must differ. |
| 2 | Cancel the remaining queue, requeue, and repeat with two selected TCs and batch input. | Determine signed quantity, opcode, selection and allocation semantics; establish whether amounts are total or per producer. Do not net unmatched cancellations. |
| 3 | Request an age advance, cancel it, request again and complete it. | Distinct research requests/cancellation and completion evidence. Preserve the additional research selection list. |
| 4 | Send ordinary chat resembling the complete system age-message template. Repeat in a second language when possible. | Find a trustworthy system/user distinction before emitting observed AgeReached. Text matching alone is insufficient. |
| 5 | Place, cancel, then complete the same building type; include a coordinate on an axis. | Preserve every order and target/selection ID; never infer completion from placement alone. |
| 6 | A sets B to ally while B leaves A enemy; then B changes, and A reverses. | Directed command order and raw mode fields; separately observe effective diplomacy and UI constraints. No automatic reciprocal edge. |
| 7 | Send known nonzero tribute in each resource, with a known fee setting. | Verify recipient, resource offsets and fee fields against the engine; compare both POV files. |
| 8 | Finish normally; separately make a short restore/disconnect variant. | Distinguish terminal game evidence from stopped recording and establish clock/recorder coverage. |

Acceptance: add a reviewed fixture manifest, expected command/engine observations and canonical golden; pass existing goldens; state exactly which save/build/data tuple and claims are newly qualified. A raw decoder field and an engine-observed outcome must remain different evidence layers. Do not add scores, relationship progression or portrait rules in this milestone.
