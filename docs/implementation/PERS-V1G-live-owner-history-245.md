## Versioned rules (never collapse these counters)

1. **Original-Game owner milestone:** at least **three distinct, current source-verified Games** under merged `AOF_PERSONALITY_THREE_GAME_UNLOCK_V1`. One BO3 can satisfy the Game count while still representing one Battle. A withdrawn/replaced original cannot remain counted; a second POV/replayed GUID does not add a Game.
2. **Ordinary profile display:** at least **three complete canonical source-qualified Battles** under `AOF_PERSONALITY_LIVE_EVIDENCE_V1`. Every required sibling Game must be current, source-accepted and correctly bound; a rejected/disputed/incomplete Game cannot promote its Battle. The Game threshold is necessary too, not a surrogate for this rule.
3. **Axis readiness:** the existing #137 longitudinal engine remains authoritative for independent Battle comparison and per-axis denominators. A source-qualified Game can contribute a raw Boomer/Aggressor commitment numerator/denominator without reviewed civ military families. Guerrilla needs attributable complete command episode arrays; Specialist needs reviewed build×civ military-family opportunities; placement/expansion need trustworthy home anchor and relevant map/start/strategic BUILD opportunity. Incompatible special starts/formats are not silently pooled.
4. **Numerical publication:** hosted numbers need owner-approved, separately versioned source/current classification and calibration (anchors, comparable cohorts, valid starting condition opportunities, recent/career weighting, military threshold/method). The old emulator-only `source-proposed-v1` 0–1 policy is NOT such approval. This PR deliberately returns null numerical values while accurately reporting measured Battles/axis coverage. A boolean or endpoint flag cannot make an unapproved SHARED_1 policy `APPROVED`.

## Source and privacy route

The existing `readMyPersonalityHistory`/INT-B collector, not a duplicated roster parser, enumerates current participant Games, checks native retained original/statistics/recorded-events hashes and artifact generations, global Game GUID claims, mapping digest, event/Season authority and official winner qualification independently of behavior, and revalidates complete data and actor permissions transactionally. No player ID/calibration/context request arguments are accepted. Results are owner-only through `requireLeaguePlayer`, ACTIVE player and linked auth UID. The new source-exact partial context uses `admitPersonalityContext(..., reviewed=null).behaviorContext`: **no guessed LAND/START or civ opportunity**. Missing context blocks only dependent axes. Historical order still uses approved plan/schedule or genuine completion; never upload order.

The profile requests this only when the viewer is the owner, the repository is live, and the existing staging/private-history client flag is enabled. It discards a changed owner/auth session and rejects a mismatched private response. On another player's page the private Personality is unavailable, not a fabricated zero. The raw private diagnostic envelopes are not sent to unrelated profiles.
