## What actually runs

\`functions/src/engines/personalityV1/personalityV1.ts\` provides three pure functions:

1. \`measurePersonalityGame\`: five automatically derived evidence fractions from a *server-verified* active READY participant statistics projection. An input must have a league Battle/Match ID, authoritative Game ID/number, replay slot/player binding, source/mapping digest, revision, accepted result and event admission; missing requirements withhold features. It does **not** itself authenticate Firestore or verify Cloud Storage digests: the upstream existing native reader must do so and pass server-only values. No browser may submit these DTOs.
2. \`buildPersonalityBattles\`: deterministically selects the highest authoritative revision for each (player, league Battle, Game), rejects equal-revision contradictory POVs and duplicate Game ordinal, then gives each league Battle **one** opportunity per axis. Multi-Game Battle feature fractions are aggregated equally only if every Game is qualified and in the same context. A late dispute, withdrawal or remapping revision supersedes old evidence.
3. \`projectPersonalityPreview\`: applies owner-supplied frozen compatible-context anchors, checks explicit independent-Battle minimums, independently produces five Developing/READY/Context-limited results, blends equal-Battle career and recent means **or medians (explicitly chosen)** using a supplied blend, and passes qualified normalized metrics through the existing \`playstyleEngine.ts\`. Returns an input-derived revision fingerprint. Outputs are marked \`PRIVATE_PREVIEW_ONLY\` even with an \`APPROVED\` string. **No registry validation, public writer, feature flag or production score is installed.**

All source inputs must come from existing observed/reconstructed projections: \`AOF_RESOURCE_COMMITMENT_V1\`, \`AOF_MILITARY_STATISTICS_V5\`, \`AOF_ENGAGEMENT_STATISTICS_V4\`, \`AOF_MAP_PRESENCE_V8\`. No replay-engine observer, player questionnaires, achievements or moral/social awards.

| Guerrilla ↔ Frontline Fighter | Attributable military **command-posture** contested episodes / qualified economy-directed + contested episodes | Raid V3 source-command episodes vs Engagement V4 battles with non-economy base classification and positively identified military instance footprint; shared source events cause ambiguity and withhold, not two votes. | Specialist ↔ Improviser | Entropy of positive **queued military-family requests** divided by log of eligible family opportunity count | Source \`military.composition\` + positive-request count; explicit civilization/map family opportunity taxonomy is mandatory, and totals must reconcile. One eligible family, missing queues, unknown amounts or unclassified families withhold. Not actual units trained or clever adaptation. |
| Compact ↔ Expansive | Distinct supported **remote economic expansion-zone placement clusters** / (distinct remote clusters + home-radius eligible economic placements) | Reuses \`mapPresence.expansionZones\` clustering and starting-TC anchor. The ratio formulas and type checks are deterministic *measurement definitions*, not authorizations for official endpoint placement. There are **no default sample thresholds, blend fractions, score-anchor ranges, strategic building IDs, qualifying family lists or episode counts**. Passing a proposed configuration produces only a local private candidate profile. Missing denominator, absent opportunity, unpriced requests, incomplete semantic classification and impossible context produce null/Developing — never zero or 50.

## Context and corrections

Each comparable context key includes topology (1v1 / fixed team / FFA), land/water/hybrid, standard/nomad/custom start, actual map ID, **server-classified duration family** (short/ordinary/etc. cutoffs pending approval), and civilization opportunity class. A different civilization may share an opportunity class only when the owner has reviewed its military options and classification. No in-season population ranking; anchors must be frozen and versioned. \`comparisonGroup\` allows explicitly approved across-context equivalence; incompatible groups are \`CONTEXT_LIMITED\`, not silently averaged.

Independent sample identity is **server-authoritative Match = league Battle**, not Game GUID, upload, POV, Event or stat artifact. Compatible Games within one Battle combine to one feature; all constituent Games need sufficient evidence. For a correction, re-read all eligible active Games from the authenticated source selectors; pass the newest revision and rebuild the pure preview. The hash includes input source lineage and configuration. The pure module is **not** a durable transactional source watcher, and final integration must use the existing read-time authority token/revision fences or atomic revalidation before publication.

## Canonical SHARED_1 compatibility and Sol handoff (Worker 3 follow-up)

**Committed converter:** functions/src/engines/personalityV1/shared1Adapter.ts. This module imports the committed domain/socialV1.ts types and invariants. It does not mutate them. Exact call order for a trusted, previously verified complete player history is:

1. Obtain only source-validated AuthorizedGame[] for **one** server-resolved league player ID, including authoritative Match/Battle and Game IDs, Game number, replay slot mapping, READY source SHA/authority revision, accepted official result, Event/Battle admission, chronological played time, format/map/start/civilization/duration and complete native/canonical statistics row. A regular Game ID (such as g1) is **not globally unique**; its identity is (league player ID, authoritative Match ID, Game ID). The league Battle ID equals the Match document ID, regardless of POV or number of Games.
2. Call projectPersonalityPreview(playerId,games,ownerCandidateCalibrationOrNull). The pure engine selects the latest authoritative revision per Game, refuses contradictory same-revision sources and multiple reuse of the same recording hash under different Games for that player, and folds all qualifying Games into a single independent Battle per axis. A current withdrawn/disputed/remapped revision supersedes previously qualified values.
3. Call toPrivateShared1Personality(preview,sameCalibrationOrNull,policyVersion). The result is an explicit PRIVATE_PREVIEW_ONLY wrapper with an array of canonical typed BattleFeature and one canonical typed PersonalityProfile. Test it using SHARED_1 JSON Schema and assertRecordInvariants. There is no trusted approval reference inside this output: policy.status is always PROPOSED and approvalRef is null.
4. Sol's INT-V1 collector, current active-source checker, owner-authorization reader, public DTO, persistence and registry-verified publication decision are **separate** implementations. Never publish this wrapper or treat the caller's approved-looking calibration status as server registry approval. Recheck source/roster/admission/result revisions before any eventual public commit. Source replacement or player remapping must invalidate and rebuild historical summaries for affected players. Missing or incompatible source evidence remains null Developing/Context-limited.

**BattleFeature meaning:** each (player, league Battle, axis) has sampleUnit=INDEPENDENT_BATTLE, Match/Battle IDs equal and a SHA-256 inputDigest over the selected source revision lineage. Its numerator/denominator represent the pure engine's **Battle-level fraction** (a multi-Game Battle is an equal mean of compatible Game fractions), not raw resource totals. normalized is a candidate 0–100 anchor transform only when that context is explicitly configured; otherwise null. Coverage is INSUFFICIENT for missing input/normalization, LIMITED for proposed candidate values. The CONTEXT evidence reference points to projection-lineage digests, **not** fabricated verified source-event execution. Raw source event IDs and model versions are retained privately in BattleEvidence. The profile's MEASUREMENT refs point to the canonical feature records. No ADMITTED gameplay-consequence or publicly approved score is asserted.

**Canonical conformance fixture:** functions/tests/fixtures/personality-shared1-conformance.json. Executable schema/guard, privacy, conflict, source-correction and identity regressions: functions/tests/personality-shared1.test.mjs. This fixture is SYNTHETIC_CONTRACT_TEST_INPUTS_ONLY; it is not a hidden sample-size or scoring policy. Tests explicitly deny proposed-profile publication through the actual SHARED_1 guard.
