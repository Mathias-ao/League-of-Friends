## What actually runs

\`functions/src/engines/personalityV1/personalityV1.ts\` provides three pure functions:

1. \`measurePersonalityGame\`: five automatically derived evidence fractions from a *server-verified* active READY participant statistics projection. An input must have a league Battle/Match ID, authoritative Game ID/number, replay slot/player binding, source/mapping digest, revision, accepted result and event admission; missing requirements withhold features. It does **not** itself authenticate Firestore or verify Cloud Storage digests: the upstream existing native reader must do so and pass server-only values. No browser may submit these DTOs.
2. \`buildPersonalityBattles\`: deterministically selects the highest authoritative revision for each (player, league Battle, Game), rejects equal-revision contradictory POVs and duplicate Game ordinal, then gives each league Battle **one** opportunity per axis. Multi-Game Battle feature fractions are aggregated equally only if every Game is qualified and in the same context. A late dispute, withdrawal or remapping revision supersedes old evidence.
3. \`projectPersonalityPreview\`: applies owner-supplied frozen compatible-context anchors, checks explicit independent-Battle minimums, independently produces five Developing/READY/Context-limited results, blends equal-Battle career and recent means **or medians (explicitly chosen)** using a supplied blend, and passes qualified normalized metrics through the existing \`playstyleEngine.ts\`. Returns an input-derived revision fingerprint. Outputs are marked \`PRIVATE_PREVIEW_ONLY\` even with an \`APPROVED\` string. **No registry validation, public writer, feature flag or production score is installed.**

All source inputs must come from existing observed/reconstructed projections: \`AOF_RESOURCE_COMMITMENT_V1\`, \`AOF_MILITARY_STATISTICS_V5\`, \`AOF_ENGAGEMENT_STATISTICS_V4\`, \`AOF_MAP_PRESENCE_V8\`. No replay-engine observer, player questionnaires, achievements or moral/social awards.

### Five independent V1 fractions (0 left; 1 right), not official scores

| Axis | Implemented source-backed primary fraction | Scope and missingness |
| --- | --- | --- |
| Boomer ↔ Aggressor | Total **positive-cost military request** share: \`military.militarySpend.resources / economy.resourceCommitment.resourcesCommitted.total\` | Whole observed Game, **not** the research report's proposed 20-minute economy share. Both models must have no unpriced commands, a positive comparable denominator, source-complete observation. Measures *request commitment*, not military strength, attack outcomes or economic effectiveness. A full-game proxy is only provisional; replace with a same-window 10/20-minute numerator **and denominator** if approved and made available. |
| Cautious ↔ Bold | Forward / (home + forward) **classified strategic placement events**, using \`mapPresence.buildingSectors.evidence\` | Strategic building IDs come from proposed/approved taxonomy config. Only unique, supported source IDs and an initial-TC anchor count. Mid-map positions are excluded, never assumed safe or forward. This is **planned placement posture**, not risk actually experienced. |
| Guerrilla ↔ Frontline Fighter | Attributable military **command-posture** contested episodes / qualified economy-directed + contested episodes | Raid V3 source-command episodes vs Engagement V4 battles with non-economy base classification and positively identified military instance footprint; shared source events cause ambiguity and withhold, not two votes. Requires a configured independent episode minimum; diplomatic FFA needs qualified dynamic relations. No claims of movement, combat, damage or actual raids. Weak semantic coverage stays Developing. |
| Specialist ↔ Improviser | Entropy of positive **queued military-family requests** divided by log of eligible family opportunity count | Source \`military.composition\` + positive-request count; explicit civilization/map family opportunity taxonomy is mandatory, and totals must reconcile. One eligible family, missing queues, unknown amounts or unclassified families withhold. Not actual units trained or clever adaptation. |
| Compact ↔ Expansive | Distinct supported **remote economic expansion-zone placement clusters** / (distinct remote clusters + home-radius eligible economic placements) | Reuses \`mapPresence.expansionZones\` clustering and starting-TC anchor. Repeated BUILDs at one remote site count once; no completed structure, survival, held territory or gold ownership implied. Nomad/no starting TC withholding is intentional until separately calibrated. |

The ratio formulas and type checks are deterministic *measurement definitions*, not authorizations for official endpoint placement. There are **no default sample thresholds, blend fractions, score-anchor ranges, strategic building IDs, qualifying family lists or episode counts**. Passing a proposed configuration produces only a local private candidate profile. Missing denominator, absent opportunity, unpriced requests, incomplete semantic classification and impossible context produce null/Developing — never zero or 50.

## Context and corrections

Each comparable context key includes topology (1v1 / fixed team / FFA), land/water/hybrid, standard/nomad/custom start, actual map ID, **server-classified duration family** (short/ordinary/etc. cutoffs pending approval), and civilization opportunity class. A different civilization may share an opportunity class only when the owner has reviewed its military options and classification. No in-season population ranking; anchors must be frozen and versioned. \`comparisonGroup\` allows explicitly approved across-context equivalence; incompatible groups are \`CONTEXT_LIMITED\`, not silently averaged.

Independent sample identity is **server-authoritative Match = league Battle**, not Game GUID, upload, POV, Event or stat artifact. Compatible Games within one Battle combine to one feature; all constituent Games need sufficient evidence. For a correction, re-read all eligible active Games from the authenticated source selectors; pass the newest revision and rebuild the pure preview. The hash includes input source lineage and configuration. The pure module is **not** a durable transactional source watcher, and final integration must use the existing read-time authority token/revision fences or atomic revalidation before publication.

## Authentic calibration study: evidence reviewed, no invented target scores

The [Codex V1b empirical audit](../research/social-v1-2026-10-17-codex-v1b-empirical.md) reports four genuine format examples, which can form candidate anchors after the *original full statistics* are reprojected with authoritative mapping and reviewed:

| Authentic case | Attributed commands | Pressure candidates | Local contest candidates | Calibration use / caveat |
| --- | ---: | ---: | ---: | --- |
| 1v1_t90-deak | 4,635 | 5 | 32 | Review economy/military commitment, positive unit queues and home/forward placements. Candidate detector labels are not executed raids. |
| 2v2_arabia | 7,363 | 15 | 68 | Verify team-role and positional comparisons; detect false shared-target or ally effects. |
| 4v4_arabia | 19,382 | 40 | 216 | Check role diversity, map sectors and source-event overlap without multiplying sample size by teammates. |
| FFA_7 (eight decoded players) | 16,817 | 56 | 162 | Test unknown dynamic diplomacy and changing-opponent source bounds; do not infer hostility from initial teams. |

The audit inspected 48,197 attributed actions, 610 source deeds and 892 pending social claims. These **do not** provide league player mapping, authoritative accepted Battle results, or reviewed actual Player Personality endpoint labels. The \`statistics-corpus-v1.json\` regression smoke checks real corpus hashes/identities, but it cannot honestly assert calibrated Player Personality output in the absence of those facts. Synthetic positive/negative feature tests exercise the computations, not real-world semantic validation.

**Proposed follow-up calibration review (no numerical proposal adopted here):** for each of the five axes, replay-project source-verified participant rows from distinct 1v1, 2v2, 4v4, FFA, naval and Nomad recordings; manually review left-pole / mixed / right-pole / weak-evidence examples. Record each numerator, denominator, catalog coverage, source IDs, context, 0–1 fraction and human judgment; seek signed-off per-context anchors, strategic placement taxonomy, eligible military families, command-episode qualification and independent-Battle minimum. Verify short Game and model-version parity. Do not choose anchor extremes from the current small friend cohort. Specifically review **whether a source-verified military-command posture legitimately corresponds to the display labels Guerrilla/Frontline Fighter**.
