# Battle and Event spotlight source safety — Worker 1 #185/#198/#201/#205

**Scope:** narrow P0 implementation companion, not a new tier, grant, scoring policy or release flag. Base main `1b5711006e70ff0e13b219cd11bbc82a37605706`. Existing draft design #192 remains owner-review only. Worker S #206 owns general Statistics tribute labels; this PR changes **only** the Event catalogue and Battle/Event UI/selector behavior.

## Settled owner-facing rules implemented

1. **Canonical Battle ≠ individual Game.** The Battle is the approved parent Match and may contain one or multiple Games. The Battle window displays **up to four measured, source-qualified highlight cards for the selected Game within its parent Battle**, independently of sibling Games, even while that Game's official winner awaits confirmation. This applies only if the Game statistics projection's explicit blocker is `Official Game result pending` and its **current accepted READY statistics pointer matches the read model's exact 64-character source hash and revision**; Game status must be READY/COMPLETED, no result dispute, no disputed/void/proposed match and no evidence truncation. This is display authority, never a permanent result, record or grant. It does not backfill Game 2 from Game 1.
2. **Victory remains official.** Battle selector has no Emperor/unbeaten/history awards; Event outcome-specific entries still require confirmed current result and pinned Emperor warm-up 1v1. Result-disputed Games currently fail closed for this local strip because no independently authenticated source-dispute classification is yet carried through to the Battle display. A pending *non-disputed* result does not erase valid source facts.
3. **Tribute is not delivered aid.** All three catalogue IDs `tributeSent:EXTRAORDINARY` (#9), `tributeSent:EXCEPTIONAL` (#31), `tributeSent:NOTABLE` (#51) remain in the 64-entry register and keep historical numbers, but are marked `SOURCE_BLOCKED` and cannot be selected in either strip. Catalogue text now describes decoded **requested** amount. `economy_statistics_v5.py` does not verify transfer/fee/recipient receipt. No amount, including a large positive request, creates an aid distinction, Bond/Chivalry or other entitlement. The raw request metric stays in Statistics, whose labels Worker S will correct.
4. **Event totals are contributions, not skill rates.** Existing Event SUM tiers and rank precedence are **unchanged**. The selected card's evidence disclosure now states the qualified number of applicable Games, total observed player-Game minutes and that the count is cumulative activity, not a per-minute skill comparison or equal-opportunity comparison. This prevents incorrect player-facing implications without replacing the owner's ranking/threshold policy. Separate intentional contribution/endurance records remain possible.
5. **No hidden effects:** at most four cards **per individually qualified Game in the parent Battle**, Event 4–5 highest qualified from the established catalogue, ties and family collapse unchanged, no filler; no achievement, Gold, League Points, reputation, relationship, trophy, Chronicle invocation, Event-accolade career receipt or grant is written or inferred. `Recognized Across Events` is a **separate proposal**, not implemented here or a 38th approved Achievement family.

## Evidence/revision and format review

- The source path is the server-projected `GameStatistics` from accepted active READY replay statistics, read through Match/Game identities. In the pending-result-only case the UI supplies the server-returned active `statisticsState`, `statisticsId`, `statisticsRevision`, result state and Game status to the pure selector; selector checks exact hash/revision and known qualification reason. **Not** a free-standing `pending=true` bypass. Unknown / invalid / stale / disputed source: zero cards.
- One-versus-one: individual raids, detected engagements, non-team queues/placements qualify by measurement; ally-only assists/co-attacks never do. Standard-start age and 20:00 checkpoint rules remain unchanged.
- Locked teams: individually attributed allied assists and common-opponent attacks remain detector descriptions only, not confirmed rescues/coordination/social Bond. Requested tribute earns no spotlight.
- Unlocked FFA: no teammate inferred from dynamic diplomacy or proximity; team-only metrics remain inapplicable. Format cohorts cannot be assumed equivalent for later record prestige.
- Multi-Game series: a **canonical Battle may have multiple Games**; selecting a Game displays only **its own** current-source Battle highlights (up to four), even when other sibling Games or the parent Battle's official winner remain pending. No new Battle identity is invented. Event totals still require complete distinct accepted Game manifest; POV uploads cannot increment the sum; corrected source replaces rather than accumulates.
- Event results and source acceptance are deliberately separate. Event roundoff final victory records/personal bests require their independent confirmed outcome/earlier comparison evidence. No source-correction acceptance can silently preserve a removed spotlight.

## Owner clarification — preserve the existing accomplishment experience (29 Oct 2026)

The established **64 ranked Event catalogue IDs, exact thresholds, rank-first and family/tie selection, 4-per-Game Battle highlights and 4–5 Event Roundoff cards** remain the approved product. The source-current pending-result exception and SOURCE_BLOCKED requested tribute are narrow correctness fixes, not a new reward design. "Distinctions" is reserved for independently qualified rare historical honours; the ordinary Battle UI uses **"Battle highlights · Game N"**, preserving its artwork, card arrangement, evidence overlay and source semantics. This document proposes **no** new tier formula, diversity rotation, universal rate normalization, skill-ranking replacement or entitlement.

The result-dispute fence is deliberately conservative: because this UI does not yet carry separate independent authority for a *result dispute* versus a *source dispute*, it withholds cards in the disputed state. That is **not** a finding that the replay source facts vanished. Independently supported future refinement would need separate owner review. Event SUM disclosures describe observed exposure, not replacement scoring.
