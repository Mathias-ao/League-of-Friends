## Executive recommendation

**Keep the recognisable 64-entry V1 catalogue as a stable migration reference, but do not mistake high absolute volume for heroism.** V1 contains 19 metric families with three numeric tiers each (57) plus seven special/history cards. The Event uses 4–5 cards and **rank before diversity**; the Battle selector reuses these Event thresholds for **one accepted Game** and truncates to four. Both deduplicate family/tier and tied holders, with no filler. An Event sums all unique accepted Games, not uploads, and keeps proven best-Game, pooled-response and weighted denominators separate. Preserve those source boundaries.

V1.1 should make the **measured deed** explicit, add **format/opportunity-aware qualification** and a distinct **single-Game threshold profile** (subject to owner/corpus calibration), elevate defensive/economic distinctiveness within *the same approved prestige band*, and demote misleading quantity-only headlines. A small elite subset should be genuinely prestigious, rather than granting an "Extraordinary" label merely because an Event contained many Games or a command-heavy player had a long recording.

## Qualification, rarity and selection policy for a prospective V1.1

1. **Authority first, no optional shortcuts.** Use one approved `eventId → matchId → gameId → current accepted sourceHash/revision` manifest per Game, not a recording upload or POV. Match/roster/current-model, official source, original event clock, dispute/void, standard-start/age/20:00, team attribution, historical baseline and source-model availability must be validated. Missing/incompatible values ⇒ `PENDING/UNAVAILABLE`, not zero. AI-warmup eligibility needs explicit recognition policy; do not infer from a normal competitive duel.
2. **Two distinct scopes.** Battle = **exactly one** accepted Game, even when its parent Match is a series, max **4**; Event = **all** accepted warm-up, main, other approved and series Games each once, 4–5, no filler. Proposed Battle pilot uses *one-Game* meaningful thresholds, not Event sum cutoffs. Event total counts remain visible but normalize suitability using `eligibleObservedMinutes`, qualified Game count and category opportunities. Never sum game-average APM or average game medians; retain duration-weighted APM/gold and pooled response median.
3. **Calibration formula, not final invented award thresholds.** For repeat counts use `ratePer30=30×distinctCount/Σ(qualified observed minutes)` as **supplemental** candidate comparability, with available/unavailable coverage and per-Game contribution distribution. Also record `nOpportunity` for defensive assists (actual ally-under-pressure windows), response (received/responded raid opportunities) and coattack (qualified common-opponent engagement opportunities). A raw count and a rate **both** matter: e.g. three tiny commands in two minutes must not become "Extraordinary". Partition by **ONE_V_ONE, LOCKED_TEAM, UNLOCKED_FFA**, game speed/age/resources/TC-start rules, real players and map size where supported. Do not rank across unsupported formats or silently presume effective diplomacy in FFA.
4. **Owner-calibration pilots (NOT approved cutoffs):** evaluate Battle `raidsOut` at **3 / 7 / 12** (N/X/E) detected episodes with ≥15 valid observed minutes; Battle `battlesFought` **3 / 6 / 10** participation episodes with independent source IDs; team-only Battle `assistsOut` and `cooperation` **1 / 2 / 4** (N/X/E) with specific ally/opponent attribution. For Event `raidsOut` consider retaining 10/20/35 only if rate/30 reaches **4/6/8**, and `response` E consider **≥5** distinct measured reactions and ≥50% qualified opportunity coverage instead of V1's 3-response minimum. These are *illustrative starting brackets*, not warranted percentile/rarity claims. Validate against genuine 1v1/4v4/FFA league corpus **before** selecting any threshold; revise by detector rate and match length, document false positive/negative exemplars. Do not make new percentile-based permanent entitlements.
5. **Prestige before raw frequency; fairness before superficial rotation.** Preserve ranks 1,2,23 as source-proven rare signals (and #45 PB separately). Then consider a **within-tier editorial shortlist**: one player/family cannot flood four cards; prioritize verified rare outcomes, specific identifiable play and distinctive category, while **never moving a Notable above an eligible Extraordinary solely to create diversity**. Keep within-family collapse, strict record+base-metric collapse, ties sharing one card and all holders. If owner retains absolute rank order, put variety in explanatory combined caption and optional "other feats" disclosure rather than secretly bypassing ranks.
6. **No social or entitlement transmutation.** `SourceSpotlight` (proposed pure presentation fact: `scope,accomplishmentId,qualifierId,gameIds,metricId,methodVersion,classification,originalWitnessRefs,actorPlayerId,beneficiaryOrTargetId?,denominator,displayValue,sourceRevision,completionStatus`) is not `Claim`, `Inference`, `AchievementGrant`, `RecordAward`, `Distinction` or social receipt. Reuse the same source reference to *link* corresponding accepted factual Chronicle scenes, Season Record Book entries or earned Achievement 2.0 tier **only if each other system independently qualified it**. Avoid second statistic, duplicate social grant or subjective labels ("hero", "betrayed", "rescued").
7. **Optional editorial combination (not a 65th card).** When two individually qualified facets describe one event — e.g. a common-opponent attack and a defender's separate action during the same eligible Game — a selected existing spotlight may have a subtitle "A shared front, while allies defended home" with two **independent event refs**; one rank, one card, no double credits, no new `metricId`, no Bond/Chivalry grant. A Chronicle callback links to its **factual** scene only; narration can say "recorded orders" / "detected pressure", never verified combat outcome.
