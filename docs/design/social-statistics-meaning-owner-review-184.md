## Decision in one paragraph

Make **Rivalry the normal story of observed, opponent-specific competition**; make **Bond and Chivalry the normal story of actor-owned, beneficiary-specific support during independently established need**; make **Gallantry conditional on challenge known *before* the offensive commitment**. Cruelty and Hostility describe *additional*, genuinely unusual contexts, never a relabeling of ordinary raiding. The social effect comes from **one independently qualified source episode per direction and track**, not a sum of `raidsOut`, `battlesFought`, `assistsOut` and `forward`. Every gameplay event may still be seen in Statistics, a factual Chronicle sentence and a curated spotlight without multiplying that same-track grade or automatically creating a permanent distinction. Tune V1 after genuine private play, but never tune away provenance.

## 1. Reading the evidence truthfully

| Symbol/term | Operational interpretation in this design |
|---|---|
| **OBSERVED_REQUEST** | Raw replay ACTION/BUILD/TRIBUTE/QUEUE with `sourceEventId`, actor, original clock and ordinal; proves command issuance, not completed attack, killed Villagers, built Castle, received food, saved allied army or motive. |
| **INFERRED_CONTEXT** | Raid V3, Engagement V4, Pair episodes, Map Presence V8/territory, Raid Response: versioned deterministic interpretations tied back to originals; not a second independently executed event. |
| **SOURCE_ADMITTED** | The **specific** #173 family method passes linked actor-owned originals + detector/context; its unchanged original #149/#158 source descriptor remains `LIMITED`. This is source-admitted **bounded inferred commitment**, not verified outcome nor owner-final numeric grant. |
| **RESULT_VERIFIED** | An independently accepted Game/Battle result; alone cannot prove directed conduct, victim weakness *before* a raid or defensive assistance. |
| **EFFECT_VERIFIED** | A separately sourced executed result / resource receipt / actual unit outcome. **Not supplied by routine existing raid, economy, BUILD or assist outputs.** |
| **PENDING / ?** | Unknown, unauthenticated, uncovered, missing counterpart, insufficient opportunity, unsupported historical order, method unavailable or genuinely undecided rule. Missing telemetry is **never zero**. |
| **0** | A genuinely observed **neutral/context-only** item, or explicit nonqualification on otherwise source-verifiable evidence; **not** a fallback for missing input. |
| **+ / ++** | Proposed ordinary / independently exceptional **strengthening** meaning; current #173 method emits only pilot `ORDINARY` under `PROPOSED_EMULATOR_ONLY`, and **no current source proof automatically earns ++**. |
| **− / −−** | Proposed independently evidenced positive **weakening action**; currently source-blocked for six tracks except separately future-reviewed methods. Never loss, nonparticipation, silence, generic peace or unasked questionnaires. |
| **Q / c / · / W** | Exact owner review: Q = conditional candidate strengthening, c = supporting context only, · = no ordinary direct effect, W = proposed independent weakening. **No symbol is itself a Claim or approved band.** |

**ID namespaces matter.** `SE id` = *base* `METRICS[].id` in `functions/src/engines/statisticsExperience.ts`; `SS id` = additional qualified `AOF_SEASON_SHOWCASE_V2` projection keys created in `functions/src/engines/seasonShowcaseProjection.ts` (`augmentSeasonShowcase`), including `battlesFought`, `goldControl`, `castles`, `towers`, `reinforcements`, `army20` and `villagers20`; `EV id` = `EVENT_SHOWCASE_METRICS[].id` in `functions/src/engines/eventRoundoffCatalogue.ts`; `RAW` = actual nested `statistics.participants[p]` field (shorthand `P.`); `SRC` = explicit source-specific metricDefinitionId/methodVersion from #149/#158/#173. A catalogue label is not an extractor field, and a Season/Event aggregate cannot satisfy a pair-directed grade. Existing `AOF_STATISTICS_ELIGIBILITY_V1` indexes 320 *TownBell capability names*, a separate eligibility taxonomy—not 320 qualified AoF social measurements.

### Explicit two-stage statistics projection — Worker 1 / Sol integration cross-check

The initial `statisticsExperience.ts` `METRICS` array deliberately defines a **base** Statistics read-model, while `functions/src/engines/seasonShowcaseProjection.ts` (version **`AOF_SEASON_SHOWCASE_V2`**) supplies a **separate existing, qualified augmentation** via `augmentSeasonShowcase(raw, game, metadata)`. It **already writes** `PlayerMeasurement.values` and `models` for Event catalogue keys `goldControl`, `battlesFought`, `army20`, `villagers20`, `farmsPlaced`, `townCenters`, `castles`, and also non-base Season keys `towers`, `reinforcements` and `garrisonsDuringRaids`. The absence of those identifiers from the base `METRICS` array is therefore **not evidence that AoF lacks the underlying metrics**; do not create replacement IDs. Age `castle` and `imperial` base metric IDs are generated, and `castle` (age time) must not be conflated with `castles` (BUILD requests).

**Verification task, not an asserted defect:** ensure that any published Event/Battle showcase or Season projection consuming `GameStatistics.players[].values` has actually received `AOF_SEASON_SHOWCASE_V2` augmentation **with its `qualifyStatistics` pass**, correct active Game source, complete Event Game manifest and model versions. A direct base-only `projectStatistics` result cannot by itself justify treating an absent later key as zero. This is a cross-surface read-model/coverage handoff, **not** social grade evidence. Separately, `tributeSent` is displayed as “resources sent” while `AOF_ECONOMY_STATISTICS_V5` observes decoded **tribute requests**—Worker 1 already raised that wording problem in [#185](https://github.com/Mathias-ao/League-of-Friends/issues/185). Neither matter changes #173 original-source method qualifications.
